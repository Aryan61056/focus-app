## Fixed since you last used it
- **Hover crash on the notch/pill.** Reproduced with synthetic pointer moves, fixed (the SwiftUI view is no longer the window's content view). Also fixed: hover never opened the panel while Focus was in the background and flickered when it did (SwiftUI hover reported "left" a few milliseconds after "entered"); an AppKit tracking area now owns hover. `tools/check_notch_hover.sh` moves the real pointer onto the panel and checks it survives and grows from 32 to 120 points (measured). The pill now sits under the menu bar on screens without a notch.
- **Monitor unplug crash.** The panel now re-places itself on display changes (`didChangeScreenParameters`) and hides when no screen exists. Not verified against a real unplug.
- **Permissions kept getting lost.** Each rebuild changed the app's signature, so macOS dropped Accessibility and Screen Recording. The bundle is now signed with a stable requirement. You must remove and re-add Focus once in Privacy & Security (Accessibility, and Screen Recording if you use screen reading).
- Permission card on Today appears between sessions and disappears once allowed; the system dialog is raised once per launch.
- Window titles now also work with Screen Recording alone.

## Added

Memory only; skips private and never-judged windows; drops text that looks like a login or payment screen. Unverified on a real display (needs your Screen Recording grant).

## Checked end to end with the real Apple model (scripted windows, fake clock; no real screen)
- Notes on the task, then a video site: the nudge card came 55 s after the switch (Standard preset). Opt-in test: `FOCUS_E2E=1 swift test --filter RealModelE2ETests`.
- Nine minutes of on-task developer windows (editor, terminal, Stack Overflow, pull request, Slack, Postman): 0 nudges. But the model said "Not sure" for most of them (only the pull request page read as "On task"), so the reading card will often say "Not sure" during real work. That is the conservative failure (nothing happens), not a false nudge; it is also why the headline recall is low. Sample of one task, not a measurement. Adding a project description that named all of those windows barely changed it (one more window read as on task), so do not promise users that describing a project fixes "Not sure".

## Matching-words rule (new, my decision, Settings switch "Count matching words as on task")
The model said "Not sure" for most real work windows, so a window whose title, page path or file path shares a distinctive word with the task or project description now counts as on task without asking the model (never on feeds, video or news sites; project allow/never rules and the never-judged list still win). On all three scenario sets it settles 33 of 62 on-task moments and waves through 2 of 45 off-task moments (both gray) and 0 of 40 unsure ones. It can only make Focus quieter, so it costs recall (a distraction sharing a word goes unnoticed), never a false nudge. These sets were also used to design it, so the numbers are a cost estimate, not held-out accuracy. It saves model calls too. With the real model, the developer-window sequence went from 1 of 9 reads "On task" to 7 of 9, and a video-site distraction still nudged at the expected time.

**Update:** the rule now also counts the app's name when the task names it ("notes in TextEdit"), except for browsers. Found by driving the real app: a README in TextEdit under that task read "Not sure". Cost on the scenario sets: off-task waved through 3 of 45 (was 2): two Figma/Android Studio gray cases where the task names the app but the window is another project. Still only quieter, never louder.

## Why clear distractions said "Not sure" (owner report 2026-10-02) and what changed
- **Cause (measured with the real model):** the first judge flagged the distraction correctly, but the second judge wrote a correct reason ("unrelated to the lab report") and then picked the category "supporting" for nearly every window, and the two-judge rule treated that as a veto. On 82 scenarios that reach the model in the app, recall on clear distractions was 47% (17 of 36).
- **Now:** (1) the second opinion is a plain question, "does this serve the task / unrelated / can't tell" (`core/prompts/instructions_v3.txt`); (2) the first judge must report confidence 95 or more before a window can count as off task (every off-task call that was really on-task work had 90 or less; the model says 95 when it is sure); (3) general-purpose apps (Finder, Terminal, Mail, Calendar, System Settings, Activity Monitor) are neutral, not judged, unless a project rule or the task names the app.
- **Result on a fresh set written before the change (39 scenarios, one run):** 11 of 15 off-task windows flagged, the other 4 stay "Not sure"; 0 of 12 on-task and 0 of 12 neutral windows flagged. On the older (spent) sets the same rule gave 88% recall with 0 on-task false flags, plus about 12 gray neutral windows (feeds, lofi video, LinkedIn) flagged, which are the cost. Small samples, one labeler; the thresholds were chosen on the older sets. Nudges still need sustained agreement in the brain, so one flagged window does nothing by itself.
- **New switch (Settings): "Judge with the on-device model"**, on by default. Off means rules and matching words only, everything else "not judged".
- **Wrong picture on Today:** the capture used the front app's biggest window, so a browser with several windows was read through another window (the words were from a different page). It now takes the topmost window of the app. Needs your Screen Recording grant to try for real.
- Tools: `FOCUS_PROBE=1 swift test --filter JudgeProbeTests` prints what each judge says about realistic windows; `FOCUS_LAB=1` compares second judges; `FOCUS_LAB_FINAL=scenarios_fresh2 swift test --filter JudgeLabTests/testShippedPipeline` runs the shipped pipeline on a set. `eval/scenarios_fresh2/` is the new set (spent after this run).
- The Python eval harness still describes the old relation judge (docs/S1-accuracy.md numbers are for it).

## Local auto-update (owner chose "local updates from this repo", 2026-10-13)
- **How:** `tools/build_app.sh` stamps every build with `FocusBuildID` (UTC timestamp, then git hash) and `FocusBuildSource` (the build folder). The copy installed in `~/Applications` (`./tools/build_app.sh --install`) checks that folder on launch, when it comes to the front and every minute (`mac/Sources/focus-app/Updater.swift`, pure check in `FocusUI/Updates.swift`). A larger ID in a bundle that has been still for 15 s and has its executable counts as newer. It then shows "A newer build of Focus is ready on this Mac" on Today and "Restart to update" in the menu bar. Settings has an "Updates" group (switch, check now).
- **Limits kept:** no network and no download; it reads a local file. Never offered and never run during a session. It never restarts without a click. "Later" hides that build until a newer one appears. Practice and everything else are unchanged.
- **Restart:** a helper shell waits for the app to exit, verifies the new bundle's signature, copies it beside the old one, swaps, and reopens. If the check or copy fails it reopens the old copy.
- **Not network updates:** Sparkle or any download would need a host, signing identity and network access in the app, which conflicts with the no-network and undecided distribution decisions. Not started.
- **Verified:** 9 new tests (newer, same, older, unstamped, still-being-written, missing executable, never its own update, hidden during a session, Later, switch off); the helper script run for real on a scratch copy of the installed app (swapped to the new build, signature valid, reopened, no leftovers) and with a broken source (old copy kept and reopened).
- **Not verified:** the banner and menu item seen live in the installed app (I did not capture your screen), and a restart triggered by clicking the button in the app. The first copy installed before this change has no build ID and must be updated once by hand with `--install`.

## Firmer by default, a climbing ladder, whole-screen gray (owner, 2026-10-13: "much more proactive as a baseline", "more punishments", "proactively check", "whole screen grayscale")
- **Why it felt lenient (found in the code):** the default preset was **Gentle** (one quiet note after about 3 minutes, no gray, no repeat), the first 3 sessions were silent practice, a dismissed card ended everything, and "persisting" only repeated the card every 5 minutes. Now: default preset **Standard**; practice mode off by default (Settings can bring it back); the old behavior is one click away (Gentle).
- **Ladder after a warning that is not answered** (`FocusUI/Escalation.swift`, driven by the brain's "interrupted" state, so it works with the Swift and Rust brains unchanged): about 40 s: **check-in** ("Are you working on <task>?", Focus reads the window again; "Yes" teaches the window and ends the climb, "Back to task" sends you back); about 100 s: **pause screen** on the pointer's screen with "That was fine" and "Snooze" held for 10 s (Back to task is never held); about 200 s: **hides the app you drifted into** (like Command-H) and brings the task forward, again every 2 minutes. Strict is faster (20 / 45 / 120 s, hold 15 s, repeat 60 s); Gentle has no ladder. Dismissing a card does not stop it; only being back on task does. Each step also raises the gray floor (70, 90, 100 percent). Switches in Settings: climb on/off, hide-app on/off, gray on/off.
- **Whole-screen gray** (`FocusUI/VeilPanel.swift`): a click-through window on every display uses a window-server backdrop layer with a saturation filter (private Core Animation classes, looked up by name) plus a faint gray wash as a fallback so it is visible either way. **Unverified:** this shell has no Screen Recording grant, so I could not see the composite. Settings has a **Preview** button (6 s of full gray). If the color does not drain, tell me; the fallback is a gray wash only. Reduce Motion is respected only in that the ramp is slow (a percent a second).
- **Bug fixed: the ghosting fade.** The veil's slow linear fade (up to a minute) was attached to the whole window content, so a session ending cross-faded the old and new Today screens over each other. The in-window saturation is gone (the gray is its own window now) and the card's animation is scoped to the card.
- **Not done on purpose:** rewards are not taken away (PRODUCT.md principle 6 and your streak rule stay; say so if you want slips to cost progress), no app is ever quit or blocked, nothing names the distraction, and the brain's own timings are unchanged (golden traces and the Rust brain still pass).
- **Fade (owner report: it went straight to gray):** Preview used to jump to 100 percent, and the ladder's own ramp took 10 s. Now Preview fades up 4 s, holds 2 s, fades down 4 s; each ladder step ramps at about 2 points a second (a first warning to full gray takes minutes); the screen updates ten times a second. A test walks a whole drift and return and fails if any second changes the gray by more than about 2.2 points. Live check: the veil window appears with the fade and is gone when it ends. How smooth it looks to the eye is unverified.
- **Intensity (owner: "very light, bump it to max"):** the brain's own veil tops out at 60 percent, so a drift only ever reached 60 percent gray, and the wash I added was faint. Now the brain's level is scaled so its cap is 100 percent (same slow rate, steeper slope: about 1.7 points a second), every ladder step from the check-in on is a 100 percent floor, and the top of the range adds a darker flat wash (32 percent) on top of fully removed color. So full gray arrives about a minute after the first flagged moment, at the latest at the check-in. Unverified by eye.
- **Honest limits:** "Yes, this is part of it" can be answered untruthfully; it only teaches that one window. The check-in's re-read uses the same judge, so a window the model calls "Not sure" still does nothing, which is also why `unsure` windows never climb. Hiding a browser hides all its windows. The pause screen is the Focus window brought forward, not a window over every display.
- **Verified:** 197 tests pass (12 new: the ladder through the real controller with a fake clock, holds, recovery, Gentle/practice/off, gray level, defaults); the 16 Rust brain traces pass; snapshots of the check-in, the notch check-in and the pause screen render. **Not verified live:** the gray on a real display, the hide, the foreground, and the sound.

## Decisions I made without asking (change any of them)
